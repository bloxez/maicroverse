# 07000.cron - Scheduled Weather Collector

## Warning

This course modifies project runtime configuration by creating API wrappers, dropping/recreating a table, and replacing cron jobs.

- Existing `weather_readings` data will be deleted.
- Existing cron jobs are deleted in setup to provide a clean learning baseline.

Run this in a learning project instance if you need to preserve production data.

## Course Goal

Build a complete scheduled ingestion workflow using mAIcro cron jobs:

1. Register an external weather API resolver.
2. Create a destination table for readings.
3. Create a cron job that runs every minute.
4. Persist weather readings for multiple cities.
5. Inspect job status and error logs.

## What You Will Build

- API wrapper: `GetWeather`
- Table: `weather_readings`
- Cron job: `australian-weather-collector`
- Scripted ingestion job: `CRON_FETCH_WEATHER.gql`

## Script Map

- `01.CRON_SETUP_WEATHER_DEMO.gql`
  - Master setup script. Creates wrapper/table and registers the cron job.
- `CRON_FETCH_WEATHER.gql`
  - Worker script executed by cron. Fetches and stores city temperatures.
- `CRON_LIST_JOBS.gql`
  - Lists current cron jobs and operational status.
- `CRON_LIST_ERRORS.gql`
  - Shows error logs for the first listed cron job.
- `QUERY_WEATHER_READINGS.gql`
  - Queries saved weather readings from the table.
- `CRON_KILL_ALL_JOBS.gql`
  - Utility script to remove all cron jobs in the project.

## How To Run

1. Run `01.CRON_SETUP_WEATHER_DEMO.gql`.
2. Wait 1-2 minutes for cron to execute.
3. Run `CRON_LIST_JOBS.gql` to confirm run count increases.
4. Run `QUERY_WEATHER_READINGS.gql` to inspect stored records.
5. If needed, run `CRON_LIST_ERRORS.gql` for troubleshooting.
