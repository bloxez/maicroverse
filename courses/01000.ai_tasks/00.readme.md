# AI Tasks

This project demonstrates scripted management of `maiql.ai_tasks` through GraphQL resolvers.

**Warning**

These scripts mutate the active project config. They create a user-defined GraphQL type, add an AI task, update it, and then delete it again.

## What This Proves

- AI tasks can be created without editing the IDE settings dialog.
- Tasks remain stored in `maiql.ai_tasks` in the same config shape used today.
- Tasks with `output_mode: "graphql_type"` must reference a GraphQL type that already exists.
- The same runtime type registry used by `TypeAdd` is used to validate task creation.

## Script Path

Script path in project storage: `scripts/1000.ai_tasks`

## Script Order

- `01.ai_task_setup.gql` - orchestrates the full setup flow in sequence
- `02.test_missing_type.gql` - negative case; attempts to create the task before `DriversLicense` exists
- `03.setup_drivers_license_type.gql` - creates the `DriversLicense` GraphQL type and the `drivers_license` document type, which uses the reusable `json_extraction` AI task

## Notes

- Run `01.ai_task_setup.gql` for the full happy-path sequence.
- `02.test_missing_type.gql` is expected to fail until the referenced type exists.
- No `DbReload` is required for these scripts because AI tasks are stored in config and user types are live in the schema.
