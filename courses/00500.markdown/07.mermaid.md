# 7. Mermaid Diagrams

A fenced block tagged `mermaid` renders as a diagram. The source stays in the file, so a
diagram can be reviewed in a pull request and fixed with a text editor.

## Flowchart

The workhorse. `TD` is top-down, `LR` is left-to-right.

```mermaid
flowchart TD
    A["Reading arrives"] --> B{"Within range?"}
    B -- yes --> C["Store reading"]
    B -- no --> D["Flag as suspect"]
    D --> E{"Third failure?"}
    E -- yes --> F["Raise site visit"]
    E -- no --> C
    C --> G["Hourly upload"]
```

Node shapes carry meaning: `["box"]` for a step, `{"diamond"}` for a decision,
`(("circle"))` for a start or end, `[("cylinder")]` for storage.

```mermaid
flowchart LR
    S(("Start")) --> P["Collect"] --> DB[("Readings table")] --> E(("End"))
```

## Sequence Diagram

Best for showing who talks to whom, and in what order.

```mermaid
sequenceDiagram
    autonumber
    participant Logger
    participant Station
    participant Hub
    Logger->>Station: Sample instruments
    Station->>Station: Validate ranges
    Station-->>Logger: Ack
    Station->>Hub: Upload batch
    alt Hub reachable
        Hub-->>Station: 200 OK
    else Hub down
        Station->>Station: Queue locally
    end
```

## State Diagram

Best for anything with a lifecycle.

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Sampling: interval elapsed
    Sampling --> Validating
    Validating --> Queued: out of range
    Validating --> Uploading: in range
    Queued --> Uploading: retry window
    Uploading --> Idle: acknowledged
    Uploading --> Queued: upload failed
```

## Class Diagram

Best for the shape of a codebase or a data model with behaviour.

```mermaid
classDiagram
    class Station {
        +String stationId
        +read() Reading
    }
    class Instrument {
        +String serial
        +sample() Number
    }
    class Reading {
        +Date recordedAt
        +Number value
    }
    Station "1" o-- "many" Instrument
    Instrument ..> Reading : produces
```

## Entity Relationship Diagram

Best for database design conversations.

```mermaid
erDiagram
    STATION ||--o{ INSTRUMENT : hosts
    INSTRUMENT ||--o{ READING : records
    STATION {
        string station_id PK
        string name
    }
    INSTRUMENT {
        string serial PK
        string kind
    }
    READING {
        datetime recorded_at
        float value
    }
```

## Gantt Chart

Best for a plan that has to fit in a page.

```mermaid
gantt
    title Winter Maintenance Window
    dateFormat YYYY-MM-DD
    section Preparation
    Order parts        :done,    p1, 2026-06-01, 10d
    Schedule access    :done,    p2, after p1, 5d
    section On Site
    Replace thermistor :active,  s1, 2026-07-01, 3d
    Recalibrate array  :         s2, after s1, 4d
    section Wrap Up
    Verify uploads     :         w1, after s2, 2d
```

## User Journey

Best for describing an experience rather than a system.

```mermaid
journey
    title Filing a daily check
    section Morning
      Walk to the mast: 4: Technician
      Record voltage: 5: Technician
    section Desk
      Enter readings: 3: Technician
      Upload batch: 5: Technician, System
```

## Pie Chart

Best for one simple proportion, and nothing more complicated than that.

```mermaid
pie title Downtime causes, last 12 months
    "Power" : 42
    "Comms" : 27
    "Instrument fault" : 19
    "Scheduled" : 12
```

## XY Chart

Best for values measured across an ordered set of categories. It supports bar and line
series, including both in the same chart.

```mermaid
xychart-beta
    title "Monthly readings"
    x-axis [Jan, Feb, Mar, Apr, May, Jun]
    y-axis "Readings" 0 --> 100
    bar [42, 55, 48, 70, 66, 82]
    line [42, 55, 48, 70, 66, 82]
```

## Quadrant Chart

Best for comparing items against two criteria and deciding where to act.

```mermaid
quadrantChart
    title Instrument response priority
    x-axis Low urgency --> High urgency
    y-axis Low impact --> High impact
    quadrant-1 Fix first
    quadrant-2 Monitor closely
    quadrant-3 Defer
    quadrant-4 Schedule
    Sensor A: [0.82, 0.78]
    Sensor B: [0.34, 0.72]
    Sensor C: [0.68, 0.30]
    Sensor D: [0.22, 0.18]
```

## Sankey Diagram

Best for showing quantities flowing between sources, stages, and destinations. Each
line is `source,target,value`.

```mermaid
sankey

Raw readings,Validated,82
Raw readings,Rejected,18
Validated,Stored,68
Validated,Alert queue,14
Stored,Dashboard,55
Stored,Archive,13
```

## Radar Chart

Best for comparing several items across the same dimensions.

```mermaid
radar-beta
    title Station health comparison
    axis Accuracy, Uptime, Battery, Signal, Calibration
    curve Station A{88, 95, 72, 90, 84}
    curve Station B{76, 82, 91, 68, 79}
    max 100
    min 0
```

## Treemap

Best for showing hierarchical proportions as nested rectangles.

```mermaid
treemap-beta
"Maintenance budget"
    "Instruments"
        "Calibration": 35
        "Replacement parts": 20
    "Operations"
        "Site visits": 25
        "Data services": 20
```

## Mindmap

Best for the early, messy stage of an idea.

```mermaid
mindmap
  root((Field station))
    Operations
      Daily checks
      Storm response
    Instruments
      Sensor array
      Calibration
    Data
      Readings
      Live stream
```

## Timeline

Best for history.

```mermaid
timeline
    title Station history
    2024 : Site survey : First mast raised
    2025 : Sensor array installed
    2026 : Live telemetry stream
```

## Practical Advice

- One diagram, one idea. Two diagrams beat one crowded one.
- Label edges when the relationship is not obvious from the nodes.
- If a diagram needs a paragraph of explanation, the diagram is wrong.
- Keep node text short. Mermaid will not wrap it for you unless you use `<br/>`.
