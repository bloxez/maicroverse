# 3. Lists And Tables

Lists and tables are how prose becomes something a reader can act on. This lesson covers
every list form Markdown supports, and the table rules that trip people up.

## Bullet Lists

Any of `-`, `*` or `+` starts a bullet. Pick one and stay consistent.

- Prepare the intake data
- Run the import
- Publish the result

## Nesting

Indent by two spaces to nest. Keep the indentation exact - three spaces here, two there,
and the list quietly falls apart.

- Run the import
  - Check the row count
  - Check the error log
    - Re-run only the failed batch
- Publish the result

## Ordered Lists

Numbers are re-sequenced when rendered, so `1.` on every line still counts correctly.
Writing them out makes the source easier to reorder.

1. Define the goal
2. Build a small example
3. Inspect the preview

Start at a different number when the list continues an earlier one:

7. Archive the raw file
8. Record the checksum

## Mixed Nesting

1. Morning round
   - Battery voltage
   - Rain gauge clear
2. Evening round
   - Upload confirmation
   - Enclosure sealed

## Tight And Loose Lists

A list with no blank lines between items renders tight and compact:

- Voltage
- Humidity
- Wind speed

A list with blank lines between items renders loose, and each item becomes a paragraph.
Use it when items need more than a few words.

- **Voltage** - drops below 11.8V trigger a site visit within 24 hours.

- **Humidity** - readings above 98% usually mean condensation, not weather.

- **Wind speed** - gusts are recorded separately from the rolling average.

## Task Lists

Task lists render as checkboxes and are perfect for runbooks and review checklists.

- [x] Battery voltage recorded
- [x] Rain gauge cleared
- [ ] Enclosure reseal check
- [ ] Upload confirmed

## Definition-Style Lists

Markdown has no definition list. The pattern that reads best is a bolded term, an em dash,
and the definition on the same line:

- **Dew point** - the temperature at which air becomes saturated.
- **Gust** - the highest three-second wind average within the reporting interval.
- **Fetch** - the distance over open water that wind has travelled before it reaches the site.

When the definitions are longer than a line, use a two-column table instead.

## Tables

A table needs a header row, a separator row, and at least one body row. Colons in the
separator set the alignment.

| Instrument | Interval | Status | Last Reading |
| :--- | :---: | :---: | ---: |
| Anemometer | 60s | Online | 14.2 kn |
| Rain gauge | 300s | Online | 0.0 mm |
| Thermistor | 60s | Degraded | 11.4 °C |
| Barometer | 300s | Offline | - |

Left, centre, centre, right. The dashes do not need to line up, but a source file that
lines up is a source file people will keep tidy.

### Formatting Inside Cells

Cells accept inline Markdown, including code, emphasis, links and escaped pipes.

| Field | Type | Notes |
| --- | --- | --- |
| `station_id` | **required** | Matches `/^CB-\d{3}$/` |
| `recorded_at` | *ISO 8601* | UTC only |
| `flags` | optional | Values `ok` \| `stale` \| `error` |

Two things a table cannot do: span cells, or contain a block element such as a list or
a code fence. When you need either, use headings and paragraphs instead.
