# Forms

**Warning**
Running the Forms setup will rebuild the aged care form definition and will replace prior demo submissions for this form.

Use a dedicated demo or testing instance when you want deterministic form content.

## Introduction

This folder contains DB-backed project scripts for the Form Completion runtime in the mAIcro IDE.

It is designed to demonstrate:

- Large multi-step form definitions stored and versioned through GraphQL
- Structured markdown + field sections that render cleanly in the Forms panel
- Realistic submission workflows with multiple applicants under one form definition
- Backend persistence via grouped submission rows keyed by `submission_id`
- End-to-end demo data suitable for UI walkthroughs, autosave testing, and validation flows

## Current Data Contract (Canonical)

The forms submission model used by these scripts is:

- `FormSubmissionSave` requires `submission_id`
- Save payload uses `responses: [FormSubmissionValueInput!]!`
- Each response row uses `field_definition_id` and `response`
- Legacy `values` and `value` naming is not used
- `03.aged_care_intake_submissions.gql` deletes previous rows for `aged_care_intake_v1` before inserting fresh demo rows

## What You Build

The setup creates one substantial aged care intake form and seeds two realistic residential aged care applicants.

Artifacts created by this folder:

| Artifact | Purpose |
|------|---------|
| aged_care_intake_v1 | Primary form definition used by the Form Completion panel |
| submission_helen_20260527 | Hospital-to-care transition scenario with dementia, falls, and family authority context |
| submission_arthur_mckenzie_20260527 | Home-to-care transition scenario with Parkinson's disease, diabetes, mobility decline, and spouse support |

Setup flow:

1. Upsert the aged care intake form definition
2. Clear prior aged care demo rows for the target form definition
3. Seed two realistic example submissions against that definition
4. Open the Forms panel and switch between submissions to review behaviour

## Scripts

- 01.form_setup.gql — Guided mAIpad-style orchestrator for form setup
- 02.aged_care_intake.gql — Upserts the full aged care form definition
- 03.aged_care_intake_submissions.gql — Deletes previous rows and seeds two realistic aged care submissions

## Suggested Demo Flow

1. Run `scripts/forms/01.form_setup.gql`
2. Open the Forms panel in the right sidebar
3. Load `FIND AGED CARE - RESIDENTIAL AGED CARE APPLICATION FORM`
4. Switch between the Helen Papadopoulos and Arthur McKenzie submissions
5. Walk through stepper sections to demonstrate markdown context, autosave, validation, and submission switching

## Notes

- The form definition is intentionally large so it exercises layout, navigation, autosave, validation, and submission grouping behaviour in the IDE.
- The seeded applicants are synthetic but written to be plausible for aged care admission demos.
- If you run `DbFullReset`, re-run `01.form_setup.gql` to restore the form and its demo submissions.
