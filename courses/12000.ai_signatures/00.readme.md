# AI Signatures With Strong Type Contracts

This course unifies signature workflows and custom type definitions into one coherent story: signatures are the product, and custom GraphQL types are the contract layer that keeps signature inputs and outputs explicit, stable, and inspectable.

## Course Goal

Build and run production-style signatures while treating type definitions as first-class contract artifacts.

You will:

- create strongly-defined supporting types for signature payloads
- create and run AI signatures that follow those contracts
- inspect signatures and type SDL side by side
- evolve signature metadata while preserving contract clarity
- validate behavior with both valid and invalid inputs

## Why This Matters

Signatures can be created quickly, but quality depends on contract discipline.

Custom types give your team a shared language for:

- expected shape of signature input
- expected shape of signature output
- discoverable schema docs in the IDE
- safer integration with wrappers and downstream consumers

## Script Map

- `01.ai_signatures_typed_setup.gql` - orchestrator for the complete guided flow
- `02.reset_signatures_and_types.gql` - repeatable baseline reset
- `03.register_supporting_types.gql` - create custom type contracts used by signatures
- `04.create_and_execute_signatures.gql` - create signatures and execute real prompts
- `05.inspect_and_evolve_signatures.gql` - inspect signatures and evolve metadata
- `06.verify_contract_alignment.gql` - validate contract behavior with positive/negative runs
- `07.cleanup_signatures_and_types.gql` - optional teardown
